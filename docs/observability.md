# Logging, errors and tracing

Every server line goes through one logger. The default writes pretty lines at `debug` in development and
JSON at `info` in production, and `createLogger({ level, format })` builds another; `level: "silent"` turns it off.
Each request gets a child logger bound to its request id, method, path and route.

`app.onError(fn)` shapes the response for a thrown value: return a `HoneyError` or a `Response`, or nothing to keep
the default. `requestLog(true)` writes one line per request when its body ends. `requestId()` assigns an id, echoes
it, and correlates it with the trace. A production error answer carries a digest, while the full stack stays in the
operator's log.

## Example

```ts
import { HoneyError, honey } from "@lovrozagar/honey"
import { createLogger } from "@lovrozagar/honey/logger"
import { requestId } from "@lovrozagar/honey/request-id"

const app = honey()
	.use(requestId())
	.logger(createLogger({ level: "info" }))
	.requestLog(true)
	.onError((error, ctx) => {
		if (error instanceof HoneyError && error.errorKey === "db_timeout") return ctx.jsonFromError(error)
		return undefined
	})

app.get("/").handler((ctx) => ctx.res.text("ok", "up"))
```

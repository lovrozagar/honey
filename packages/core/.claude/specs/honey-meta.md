# Honey Meta

## Goal

Typed route metadata via `.meta<T>()` generic on the honey chain (tRPC pattern). Meta enriches codegen artifacts, is available at runtime via `ctx.meta`, and generates full type safety through `honey.gen.d.ts` and `InferRouteMeta`.

## Scope

- In: `.meta<T>()` generic chain method, built-in `openApi` default shape, `ctx.meta` in handlers, meta in `honey.gen.d.ts`, `InferRouteMeta` + `InferMeta` utility types, meta flowing through all 3 codegen artifacts, demo usage
- Out: SDK meta (future)

## Design

### API

```typescript
/* built-in — always available */
type OpenApiMeta = {
  deprecated?: boolean
  description?: string
  operationId?: string
  security?: Array<Record<string, string[]>>
  summary?: string
  tags?: string[]
}

type DefaultMeta = {
  openApi?: OpenApiMeta
}

/* .meta<T>() sets the user meta type. Final shape = DefaultMeta & T */
const base = honey<Env>()
  .meta<{ rateLimit?: "strict" | "default"; auth?: "public" | "required" }>()
  .use(withAuth)

/* route .meta() is typed against DefaultMeta & T */
base
  .get("/orgs")
  .meta({
    auth: "required",
    openApi: { summary: "List orgs", tags: ["Organization"] },
    rateLimit: "strict",
  })
  .handler((c) => {
    c.meta.auth       // "required" — narrowed literal
    c.meta.rateLimit  // "strict" — narrowed literal
  })

/* without .meta<T>(), routes get DefaultMeta only */
honey<Env>()
  .get("/health")
  .meta({ openApi: { summary: "Health check" } })
  .handler(...)
```

### .meta<T>() — empty generic call on Honey

Like tRPC's `initTRPC.meta<T>().create()`. Call takes no arguments — just sets the generic type parameter that propagates to all downstream `RouteBuilder.meta()` calls.

```typescript
/* on Honey class */
meta<TMeta extends Record<string, unknown>>(): Honey<TEnv, TCtx, TMeta>
```

Returns same instance with `TMeta` captured. `RouteBuilder.meta()` then accepts `Partial<DefaultMeta & TMeta>`.

### ctx.meta — runtime access (narrowed)

Handlers access their route's meta via `ctx.meta`. The type is narrowed to exactly what was passed in `.meta()`, not the broad union from `.meta<T>()`.

```typescript
base
	.get("/orgs")
	.meta({ auth: "required", rateLimit: "strict" })
	.handler((c) => {
		c.meta.auth // "required"      — literal, not "public" | "required"
		c.meta.rateLimit // "strict"        — literal, not "strict" | "default" | undefined
	})

base
	.get("/health")
	.meta({ auth: "public" })
	.handler((c) => {
		c.meta.auth // "public"        — narrowed
		c.meta.rateLimit // undefined       — wasn't passed
	})
```

Implementation: `.meta()` captures actual value type via generic:

```typescript
meta<TRouteMeta extends Partial<DefaultMeta & TMeta>>(
  meta: TRouteMeta
): RouteBuilder<..., TAccMeta & TRouteMeta>
```

Multiple `.meta()` calls accumulate (shallow merge at runtime, intersection at type level).

- `ctx.meta` is namespaced — no collision with middleware additions (`ctx.userId`, `ctx.db`)
- `Readonly` — meta is immutable at runtime
- Routes without `.meta()` get `{}` (empty object)

### honey.gen.d.ts — meta in generated types

The type generator emits `meta` per route in the `Routes` type. **Full meta including openApi** — complete contract for SDK generators, type inference, and external consumers.

```typescript
/* auto-generated by honey — do not edit */

import type { HoneyContext } from "@lovrozagar/honey"

export type BaseCtx = Omit<HoneyContext<{ SECRET: string }> & { db: ...; userId: string }, "json">

export type Routes = {
  "/orgs": {
    get: {
      ctx: BaseCtx & { input: { search: { limit: number; offset: number } } }
      input: { search: { limit: number; offset: number } }
      meta: { auth: "required"; openApi: { operationId: "listOrgs"; summary: "List orgs"; tags: ["Organization"] }; rateLimit: "strict" }
      output: { "application/json": { ok: { items: string[]; total: number } } }
    }
    post: {
      ctx: BaseCtx & { input: { json: { name: string; slug: string } } }
      input: { json: { name: string; slug: string } }
      meta: { auth: "required"; openApi: { summary: "Create org"; tags: ["Organization"] } }
      output: {}
    }
  }
  "/orgs/:orgId": {
    get: {
      ctx: BaseCtx
      input: {}
      meta: { auth: "required" }
      output: {}
    }
  }
}
```

### InferRouteMeta + InferMeta utility types

```typescript
/* Extract meta type for a specific route */
export type InferRouteMeta<
	T,
	TPath extends InferRoutePaths<T>,
	TMethod extends InferRouteMethods<T, TPath>,
> = RouteLookup<T, TPath, TMethod> extends { meta: infer M } ? M : never

/* Extract the TMeta generic from a Honey instance */
export type InferMeta<T> = T extends { readonly $meta: infer M } ? M : never
```

Usage:

```typescript
import type { InferRouteMeta } from "@lovrozagar/honey"
import type { Routes } from "./honey.gen"

type OrgListMeta = InferRouteMeta<Routes, "/orgs", "get">
// { auth: "required"; rateLimit: "strict" }

/* or from the app directly */
import type { app } from "./app"
type AppMeta = InferMeta<typeof app>
// { auth?: "public" | "required"; rateLimit?: "strict" | "default" }
```

### Codegen artifact flow

| Field in meta | routes.gen.ts `meta` export | honey.gen.d.ts `Routes` | manifest.gen.json | openapi.gen.json                | ctx.meta                  |
| ------------- | --------------------------- | ----------------------- | ----------------- | ------------------------------- | ------------------------- |
| `openApi.*`   | **included**                | **included**            | included          | **consumed** → operation fields | **excluded** (type-level) |
| custom fields | **included**                | **included**            | included          | excluded                        | **included**              |

#### routes.gen.ts

```typescript
/* auto-generated */
import type { TreeNode, RouteHandler } from "@lovrozagar/honey/tree"

/* runtime routing tree — no meta */
export const tree: TreeNode = { ... }

/* route metadata — for gateway/middleware consumers, openApi stripped */
export const meta: Record<string, Record<string, unknown>> = {
  "GET /orgs": { auth: "required", rateLimit: "strict" },
  "POST /orgs": { auth: "required" },
  "GET /orgs/:orgId": { auth: "required" },
}
```

Key format: `"METHOD /path"`. `openApi` field stripped.

#### manifest.gen.json

Full meta on each route entry (openApi + custom). Already works this way.

#### openapi.gen.json

Reads `meta.openApi` per route → maps to OpenAPI operation fields:

- `summary` → `operation.summary`
- `description` → `operation.description`
- `tags` → `operation.tags`
- `deprecated` → `operation.deprecated`
- `operationId` → `operation.operationId`
- `security` → `operation.security`

Already partially implemented (summary, tags, deprecated). Add description, operationId, security.

## Decisions

- Generic on chain (`.meta<T>()`) over module augmentation — no ambient files needed
- `openApi` is built-in default, always available — user meta extends it
- `ctx.meta` namespaced — static metadata separate from dynamic middleware additions
- `ctx.meta` is `Readonly` — immutable at runtime
- `ctx.meta` type is narrowed to exact literals passed in `.meta()`, not the broad TMeta union
- `honey.gen.d.ts` includes `meta` per route — full meta including openApi
- `InferRouteMeta` extracts meta from Routes type, `InferMeta` extracts TMeta from app instance
- All codegen artifacts include full meta (openApi + custom)
- Only `ctx.meta` strips openApi at type level — handlers don't need docs metadata in autocomplete
- openApi data stays on handler.mt at runtime (~300-500 bytes/route, negligible)
- Key format for meta export: `"METHOD /path"` (same as spec)

## Rejected

- Module augmentation for RouteMeta — requires ambient `.d.ts` file, less discoverable
- Flat meta on ctx (no namespace) — collision risk with middleware additions, muddy boundary between static vs dynamic
- Meta on tree handler nodes (mt field) — bloats routing structure with codegen-only data
- Fully opt-in openApi (no default) — too much ceremony for the common case
- Configurable tree meta keys — unnecessary complexity, simple rule (all non-openApi) is sufficient
- Stripping openApi from codegen artifacts — openApi is part of the full route contract, only ctx.meta hides it

# Regression matrix: workstreams 9–12

OpenAPI and the manifest, codegen (TypeScript, type extraction, MCP, Go, Rust, Python, Go CLI), the
client runtimes, and tooling.

Most findings here were already guarded by tests that the codegen, client and tooling lanes wrote
alongside their fixes. Each of those tests was run against `3ab88ce` on its own, and the reason for
the failure was checked; they now carry a `// regression: <id>` comment. Findings with no such
test got a new one in `packages/core/tests/regression/ws9-12/`:

- `typescript.regression.test.ts`: generated TypeScript that must parse (H40), schema-name hash
  collisions, trailing slashes in spec paths, and the `ctx.retry()` failure path.
- `tooling.regression.test.ts`: generated-file writes, watch globs, stale outputs, the CLI watch
  loop and the Node config hand-off.
- `polyglot.regression.test.ts` (opt-in, `test:harness`): the Go, Rust, Python and Go CLI SDKs.
  Runtime findings run the programs in `checks/` against a mock server in the test process that
  records every request; the programs use only API that both trees generate, so one build per
  language serves every check, and Go reaches methods through reflection so a signature that
  differs between the trees fails one check, not the build. Compile findings generate an SDK from
  a one-finding document and compile it with `go vet`, `cargo check`, or `compileall` plus mypy.
  Point `HONEY_PYTHON` at an interpreter with `httpx` (and `mypy`) to run the Python half.

Abbreviations: `ts` = `regression/ws9-12/typescript.regression.test.ts`, `tooling` =
`regression/ws9-12/tooling.regression.test.ts`, `poly` = `regression/ws9-12/polyglot.regression.test.ts`;
other paths are relative to `packages/core/tests/`. "Yes" means the test fails on `3ab88ce` for the
reason the finding describes; the observed failure follows.

Scope: Critical, High and Medium findings, plus the Lows that were cheap. Findings in the
realtime protocol (resume, ready, ping, long-poll, the SDK resumable connections) are deferred by
the realtime decision and are not listed, except where a crash fix shipped.

## Findings not fixed on HEAD

- **H50, Python multipart.** The SDK passes httpx a list of `(key, value)` tuples as `data`. httpx
  0.28 cannot encode that beside `files`: a file plus a text field raises `TypeError`, and a file
  alone is sent with an empty body. Repro: `httpx.Request("POST", "http://x/u", data=[("name", "n")], files=[("file", b"x")]).read()`
  raises; with `data=[]` the body is empty. The poly test "Python runtime H50: a multipart body is
  sent" is skipped until this is fixed.
- **New on HEAD: Rust SDK with a bare object response.** A response schema `{ "type": "object" }`
  generates `HashMap<String, serde_json::Value>` in `src/resources/*.rs` without importing
  `HashMap`, so the crate does not compile (E0425). `3ab88ce` returned `serde_json::Value` and
  compiled. Repro: one operation with that response, then `cargo check`.
- **Go CLI, missing required flag.** `demo items get` without `--id` exits 3 (network) instead of 4
  (usage).

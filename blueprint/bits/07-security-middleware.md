# Bit 07 — security + edge middleware

Closes: A5 (rate-limit) · A6 (compress) · F1 (adversarial gate per middleware) · G1 (telemetry nesting + traceparent) · H17 (observability surface)
Oracle kept green: `tests/integration/cors.test.ts`, `tests/integration/proxy.test.ts`, `tests/integration/static.test.ts`, hostile-client suite.

## Scope
The composable edge middlewares: cors, secure-headers, csrf, request-id, timeout, server-timing, powered-by, ip-restrict, plus the two new ones — `rateLimit` (A5) and `compress` (A6). Also proxy/gateway, static files (with range from bit 05), i18n, crypto, observability (curl-logger, request-to-curl, logger). Each middleware carries an adversarial case (F1).

**Rulings (bit 07).** Two H23 violations verified in v0 and cut; four more calls ruled.
1. **Proxy is a plain handler factory, no slot, no builder method.** v0 self-registers (`registerFeature("proxy", …)`, part of the `feature-slots.ts` registry cut at bit 06) and grows a `.proxy(config)` route terminal that does `requireFeature("proxy")`. v1: `import { proxy } from "@lovrozagar/honey/proxy"`, used as `app.all("/api/*rest").handler(proxy({ upstream, … }))`; core never imports proxy, an app without it bundles none of it. Its response is the **passthrough brand `TypedResponse<string, string>`** (the upstream decides status and content type, so a proxied route is opaque to typed narrowing) — one handler type, no core change; the SDK emits a raw-response accessor for it at bit 11+ (a proxied route stays listed/callable, just untyped — not excluded).
2. **i18n's module runtime slot is CUT.** v0's `i18n-slot.ts` keeps `let runtime` with `registerI18nRuntime`/`getI18nRuntime`, and error rendering does `loadHoneyFeature("i18n")` then `getI18nRuntime().translateError` — a global slot plus a hidden specifier import (verified). v1: `errorI18n({ errors, fieldNames, resolveLocale })` returns a **value** `{ resolveLocale, translate(error, locale) }`; the app carries it with `app.errorI18n(value)`; core calls `settings.errorI18n?.translate(…)` and never imports i18n. `slot.ts` is deleted (replaced by `error-i18n.ts`).
3. **One logger value, `app.logger(value)`, threaded to every reporter.** A single app setting (a value, like `wsAdapter`/`errorI18n`), read from settings by dispatch, the ws and realtime sessions, the stream/sse/generate producers, and the Node bridge's default reporter — this is where the bit-05/06 `log: null` and "wired at bit 07" deferrals land. No console fallback anywhere (matches `invoke-user`); `process.emitWarning` stays the Node-bridge default **only when no logger is set** (and only there, since it is node-adapter-local, never in portable core). Three distinct, non-redundant seams: `app.onError` (awaited, response-**shaping**), `app.logger` (operational structured log), `telemetry.onError` (fire-and-forget **reporter**).
4. **`tap` is core and gets rows.** `app.tap(key, handler)` + `ctx.tap` — a post-response observation hook, contained through `invokeUser`, that never delays or shapes the response. 74 cases moved from bit 02, no row existed; added `src/routing/tap.ts` (+test) and `tests/types/tap.typetest.ts`.
5. **`otelAdapter(api)` takes the OpenTelemetry API as a value** — no `@opentelemetry/api` import in honey, no optional peer, nothing to load; also guarantees one shared OTel instance. (The asymmetry with `ws` as an optional peer is justified: `ws` is a whole server impl honey must load; the OTel API is a thin surface the app already holds, and sharing the app's instance is a correctness win.)
6. **Phasing** (bit 07 ≈ bits 04+05+06 combined), a ping per phase: (a) the observability seam first — `logger`, `log-format`, `fields`, `request-log`, `on-error` — since everything else reports through it; (b) the edge middlewares (cors, secureHeaders, csrf, requestId, timeout, serverTiming, poweredBy, ipRestrict) + `rateLimit` + `compress`; (c) proxy + static + crypto + curlLogger/requestToCurl; (d) i18n (284); (e) tap; (f) telemetry (otel, traceparent, span-lifecycle, correlation, observability-matrix); (g) the security corpus + fuzz + one guard per middleware + the `mw-stack` perf gate + the 1074-case accounting.

Module state goes per-instance (H23, no-module-state): `crypto`'s `cachedKey` → one cache per signer built from a secret; i18n's `pluralRulesCache` → an i18n-instance field; `rateLimit`'s memory store → a per-middleware closure, bounded LRU/TTL (H18.8). No `Symbol.for("honey.replaceBody")` seam — `curlLogger({ body: true })` reads `request.clone()` (verified: the clone and the handler's own first read both see the body), and `bodyLimit` uses the adapter's existing `BODY_OVERFLOW`. `rateLimit` keys by `ctx.ip` (the platform peer; trust is cut, so a spoofed `X-Forwarded-For` cannot rotate keys — corpus case). `compress` default-excludes `Set-Cookie`/auth-bearing responses (BREACH) and hard-skips produced streams.

**Phase (a) — the observability seam (6 calls ruled; `dx/observability.md` updated to match):**
- **(a1) The default logger is a real sink, not a "fallback."** `app.logger`'s default is `createLogger()` writing through its own sink (`process.stdout.write`, else `console.log` on Workers); `settings.logger` is **never null** (the default, or a `logger:false`/`silent` no-op). "No console fallback" (Ruling 3) means no ad-hoc `console.*`/`emitWarning` outside a logger's sink — a structured leveled sink is not a fallback. Consequence: the Node bridge's `emitWarning` default is **CUT** — the bridge reports serve-level failures through `settings.logger` (which always exists), so Ruling 3's "emitWarning when no logger is set" case never arises; the serve `onError` option stays as a user override, defaulting to the logger. v0 `342ac7baf3` ("no logger → errors swallowed silently") **inverts** (re-authored: unconfigured errors reach the default logger — H17, nothing is swallowed). **Bun aligns with Node (closed-bit-04 change, ruled):** with no `onError`, `bun/serve.ts` installs a `Bun.serve` `error` handler that logs "serve failed" through `settings.logger` and returns a plain 500 — not Bun's own error page, which renders the **stack** in development (a private-stack leak) and writes outside the sink. Same sink, same 500, no stack page on every runtime; a user `onError` still overrides. Bit-04's "Bun's own error page unless onError is set" case is re-authored to the aligned behavior. This is an H17 hardening (uniform cross-runtime, no stack leak), not a regression.
- **(a2) dev/prod from `NODE_ENV`, read once and guarded** (`globalThis.process?.env?.NODE_ENV`): `production` → json/info; `development` → pretty/debug; `test` → silent (a test asserting logs passes its own logger); **unset or unreadable (Workers) → prod defaults** — fail closed (json, generic errors, no stack leak) rather than leak a stack because `NODE_ENV` was forgotten. No `app.mode()` knob (as there is no `logLevel` knob, H17).
- **(a3) `digest`:** 16 hex from `crypto.getRandomValues`, **random per occurrence (never derived from the error)**, on the client envelope of an **unknown thrown value's 5xx projection only** (named `HoneyError`s unchanged), the same value on the operator line. The SDK error type gains an optional `digest?` at bit 11.
- **(a4) `app.requestLog(true | { skip(entry) })`, off by default:** one `info` line after the body ends, or `status: "aborted"` on a cancel; the counting `TransformStream` wraps the body **only when on**. Fields `method/path(no query)/status/durationMs/routeId/kind/requestId/runtime/bytes?`; `kind` from the response brand; **no `cache`** (no v1 source). `requestLog:true` + `logger:false` → throws at finalize, naming both.
- **(a5) `ctx.log`:** a reserved ctx key, a **lazy prototype getter** building a per-request child on first access (zero allocation if never used), binding `method`/`path`(no query)/`routeId` + `requestId` when phase-(b) `requestId` set one. v0's `logger()` middleware is gone — split into `app.logger` + `app.requestLog` + `ctx.log`; its 7 cases re-authored onto the request log, none ported as middleware.
- **(a6) `onError` fires on thrown errors only.** A thrown error — a named `HoneyError` 4xx included — reaches `app.onError` (the v0 oracle `86bd39b9e3` and anyrow depend on it); a **framework-generated status answer** (no-route 404, 405, 308 trailing-slash, 426, 400 bad-path) does **not** (nothing thrown; `onNotFound`/`onMethodNotAllowed`/none). Both halves pinned in `errors/on-error.test.ts`.
- **(a7) A crashed custom error formatter is logged, not swallowed** (`projector.ts:69`). `errorBody` keeps falling back to the error's unformatted `data` (the client still gets a well-formed error), but the crash is now reported: `createErrorResponse` takes an optional `report?` callback, threaded from the request-scoped answer paths that hold `settings.logger` (`on-error.ts`, `dispatch` make404/make405), and the catch calls `report?.(e)` → `logger.error({ err }, "error formatter failed")` per crash (loud on a persistently-crashing formatter, by design). `projector.ts` stays pure — a callback parameter, never a logger import. The pre-built `fixedNotFound` fast path is unaffected (it runs only when `customErrorFormatter === null`, so no custom formatter crashes there).

**Phase (b) — the trust replacement (ruled before build):**
- **(b1) `InboundTrust`, explicit per-feature opt-in, default never.** `trustProxy` is cut (H23), so there is no proxy-count/CIDR signal to decide "may this hop hand me an id or a trace", and v0 reused any valid inbound id with **no** gate (a log/header-injection weakness). The replacement is one shared value type — `type InboundTrust = boolean | ((ctx: { readonly ip: string | null; readonly req: Request }) => boolean)` — exported from `src/middleware/request-id.ts` (telemetry imports the type only). `requestId({ header, generate, validate, trustInbound = false })`: `false` (default) always generates a fresh id (the anyrow "trustProxy off" pin); `true` reuses a valid inbound id (behind one's own gateway); a predicate decides per request (`({ ip }) => ip === gatewayIp`, or a shared-secret header check) — plain code for the self-hosted-proxy case, not X-Forwarded-For machinery. `validate` always applies on top, so even a trusted hop cannot inject arbitrary text into logs or headers. `otelAdapter(api, { trustInbound = false })` (phase f) uses the same type: `false` links an inbound `traceparent` (never continues) and the request id stays honey's own; `true`/predicate continues. Default-never is fail-closed and parity with v0's effective default (`trustProxy` defaulted to 0). Rejected: an app-level `app.trustInbound` (global, couples features that may trust different hops), a proxy-count/CIDR list (the machinery H23 cut), a boolean-only form (loses the self-hosted-gateway case).
- **(b2) `ipRestrict` keeps CIDR rules — policy on `ctx.ip`, not the cut trust-CIDR.** H23 cut `ip.ts`'s CIDR as part of `src/trust/*` (the XFF *resolution* that decided **who the client is** via proxy ranges), and its "no CIDR" modifies `ctx.ip` resolution (`ctx.ip` never uses CIDR to find the peer). `ipRestrict`'s CIDR is a different thing: an allow/deny **filter** on the already-decided canonical `ctx.ip`, so IPv4/IPv6 CIDR rules stay, as plain code local to `src/middleware/ip-restrict.ts` (no shared `ip.ts`, no trust module; ~120 lines reached only through the explicit import, tree-shakeable). A parser is needed regardless — `ctx.ip` unwraps `::ffff:` and lowercases but does not expand IPv6 zero-compression, so rules can't be string-compared — which makes CIDR marginal over the parser, and exact-IP-only would miss the main use (webhook-sender ranges, VPN/office subnets). Cut: v0's `getIp(req)` override (the XFF footgun H23 removed, per-middleware) and the legacy `trustProxy`/`trustCloudflare` migration throw (no `app.trustProxy` to point at). Fail-closed: a null or unparseable `ctx.ip` is 403 under either list, deny is checked before allow, a refusal is `HoneyError forbidden` with `mw.errors = ["forbidden"]`. Construction still throws on an invalid rule, an empty `allowList`, or no lists. Retire the 3 trustProxy/XFF cases + the "behind one proxy" consumer case (H23) and the `getIp` case; the rest port. F1: a spoofed `X-Forwarded-For`/off-Workers `CF-Connecting-IP` can't move `ctx.ip` into the allow list, and `::ffff:`-mapped / zero-expanded forms can't slip a deny rule; the guard string-compares rules. (The shared-parser deviation — `ipRestrict` imports `peer.ts`'s `parseIpv4`/`parseIpv6` rather than copying — is **approved**: `peer.ts` is the surviving bit-03 `ctx.ip` module, not the cut `src/trust/*`, and one parser means a rule and `ctx.ip` can't canonicalize differently and let a spelling slip; only the CIDR mask/range logic is local. The export is additive and internal-only.)
- **(b3) `compress` is gzip-only for dynamic answers; brotli is for precompressed static (phase c).** Measured: `CompressionStream` has no quality knob and runs brotli at quality 11 — ~55× gzip's time (bun: 23 µs → 1297 µs on 2.3 KB JSON; a 4 KiB answer is 1.29 ms vs 42 µs) to save ~2×. A dynamic-brotli option's only effect is a ~50× request-path slowdown, so it is not offered — `compress` encodes **gzip only**, no `br`, no option. Brotli's home is a `.br` sibling served by phase-(c) static serving. Rejected the fallback ("br only when the client ranks it strictly higher") — a client can rank br higher and eat 1.29 ms; gzip-only is the clean call. Updates the dx row to "gzip by `Accept-Encoding`; br for precompressed static (c)". The committed `negotiate`'s br-on-tie is changed to gzip-only. `compress` otherwise correct: encodes `rawBodyOf` only (never reads/clones a stream — produced sse/stream/generate pass through, a never-ending stream answered at once unencoded), BREACH default-exclude (request `Cookie`/`Authorization` **and** response `Set-Cookie`, since BREACH needs ambient credentials a cross-site attacker can make the browser send — `Authorization` can't be forged cross-site but the inclusion is harmless and matches the ambient-credential model), skips 1xx/204/206/304/already-encoded/`Content-Range`/`no-transform`/non-compressible/sub-threshold, drops stale `Content-Length`, `Vary: Accept-Encoding` on every eligible answer.
- **(b4) Error answers stay on the plain path on Node (closed-bit-02 `projector` change, ruled — completes the bit-07 plain-path pin).** The boundary's `createErrorResponse` builds a native `Response`, so on Node every header-middleware write on a 4xx/5xx goes to native `Headers` — off the plain path, for thrown 500s, framework 4xx, **and the 429 flood** (a rate-limited attack is all 429s — the hot path under attack). Fix in **bit 07** (the "mutate the plain record, never force native Headers" pin is bit 07's): when the request is Node-outbound (`isNodeOutbound(req)`, as `ctx.res` already decides), the boundary builds the error answer with `createHoneyResponse({ headers, raw, status })`. Wire-identical (the Node writer handles a `HoneyResponse`; `onError`'s own returned `Response` passes through untouched). Scope: `errors/projector.ts` (`createErrorResponse` takes the node flag/request) + call sites in `errors/on-error.ts` and `routing/dispatch.ts`; the pre-built `fixedNotFound` fast path follows the same node-aware treatment (or stays the one documented native residual if that would cost the fast path — implementer's call, but `(C)` must then mark it). **No guard** (a perf pin, not a security property). `(C)` asserts `isHoneyResponse` at the bridge for 200 / thrown-500 / 429 / 404 / 405 — the exact proof (counting `new Headers` reads 0 even on native error answers, since `new Response(body,{headers})` builds them internally).

- **(c6) `staticFiles` is resolve-based (S1–S7).** `staticFiles({ resolve, prefix?, headers?, rewritePath?, precompressed? })` — a middleware around `resolve(ctx, filePath)`, **not** a `root: string` (which would force `node:fs` into portable core; `resolve` is runtime-agnostic — ASSETS/`Bun.file`/node-fs/KV). dx row corrected to `resolve` (same draft-vs-code mismatch as proxy; no consumer calls it, so nothing breaks). In-bit-07 plain-path work (the pin is bit 07's), same precedent as b4's bit-02 `projector` change. No guard (perf pin).

F1: a prototype-named query/var (`?lang=__proto__`, a `constructor` branch) and a shared error translated per request/locale pollute nothing and never mutate the thrown error; guard = a `translate` that mutates the thrown error's message in place.

**Phase (e) — tap (T1–T7 ruled):**
- **(e1) Placement:** `src/routing/tap.ts` holds the runtime (the settings `taps` Map + post-response firing); `app.tap(key, handler)` and `.taps<T>()` on the app/settings chain; `ctx.tap(key, payload)` a context method over a **lazy per-request queue**; `tap` is a RESERVED ctx key; `tests/types/tap.typetest.ts` for the typing.
- **(e2) Fires only after a successful handler answer** (v0 parity): after the chain resolves, when the route's handler returned the answer **and** nothing recorded an error after it (`ctx.error` unset) — a middleware throw after `next()`, a middleware that answers without the handler (cors preflight, a 429), a thrown `HoneyError`/unknown throw, 404/405, and a 101 all fire **no** taps. A per-request flag set by the handler terminal gates it; with no taps registered nothing is allocated (the queue is lazy). The success-only mirror of (a6)'s onError-fires-on-thrown-only.
- **(e3) Contained through `invokeUser`, at v0's severity.** Each tap runs as `ctx.background(invokeUser(() => fn(ctx, payload), { log, phase: "tap", fields: { tap: key }, onError }))` — the shared never-rejects containment (so `background` never sees a rejection). But **keep v0's `warn "tap failed"`**, not `invokeUser`'s default `error "callback failed"`: pass `onError = (err) => logger.warn({ …bindings, tap: key, err }, "tap failed")`. H22 parity, and a fire-and-forget observation hook failing is a warning, not an error (the response already went out); the containment is shared, the severity stays v0's.
- **(e4) Order/payloads (v0):** meta-driven taps fire **before** dynamic (`ctx.tap`) ones, each in registration/call order; a meta tap gets the exact meta value (route over chain); the same key can fire from both; a payload passes as given (no copy).
- **(e5) Mounted apps (v0):** at finalize a plan's taps are the **serving app's merged over its source app's** (serving wins), computed once per plan so dispatch reads one Map.
- **(e6) `TapContext<TEnv>`:** `background`/`env`/`headers`/`meta`/`params`/`path`/`req`/`routePattern`/`search` — **no `res`, no `tap`** (a tap can't send a response or recurse); middleware additions stay reachable at runtime (v0) but aren't typed.
- **(e7) Deferrals:** `750eab7295` (taps + telemetry coexist) → phase (f); `d61bb1924d`/`339d1aec69` (waitUntil) port here against `ctx.background`. F1/guard: a tap that throws or never settles never delays or changes the answer, never reaches `onError`, never fires on an error answer; the guard fires taps before the answer, inline and awaited.
- **(c7) `crypto` ships only `timingSafeEqual`, stateless (C1–C2).** The module-level `cachedKey` (H23/no-module-state) is replaced by a **fresh random HMAC key per call** (`getRandomValues(32)` → `importKey`): no state, the `timingSafeEqual(a, b)` API is unchanged, +6 µs on node is noise for a once-per-request auth check, and a per-call key is strictly stronger than a process-lifetime one (nothing to recover across calls). Rejected a `createComparer()` factory (surface to save 6 µs) and per-call `generateKey` (worse). dx/crypto.md is **trimmed to `timingSafeEqual`** — HMAC sign/verify, random id/token and base64url were never in v0's crypto (cookie signing already covers HMAC; `randomUUID`/`getRandomValues` are platform; webhook verify (B3) brings its own helper + suite when scheduled). It keeps v0's semantics: HMAC both sides then `subtle.verify` (no length/content leak), UTF-16-code-unit string compare (lone surrogates don't collapse), a string never equals bytes. F1: equal-length first-byte-wrong vs last-byte-wrong both false, length-mismatch false; guard kills a UTF-8-bytes comparer (which equates two different lone surrogates — the one property a naive compare breaks). Timing itself isn't deterministically testable, so no case claims it.
- **(c8) `curlLogger`/`requestToCurl` (L1–L4).** Body capture is `request.clone()` taken before `next()` only when body logging is on and the type is allowed (opt-in cost), bounded (`maxBytes` 16 KiB, cut early + branch cancelled), never rejects (an omitted reason is logged). Default sink is `ctx.log.info({…}, "request curl")` (the one app logger — respects `logger(false)`/levels); a `log` custom sink stays, `instance` is cut (the app logger replaces it); a failing redact/skip/sink → `ctx.log.error({ err }, "curlLogger failed")`, never a 500. **One redaction definition:** widen `fields.ts` `isSensitiveHeader` to the union (+`x-csrf-token`, `x-xsrf-token`, + `/(?:^|-)(?:token|secret|api-?key|password|session)(?:$|-)/i`) and have `curlLogger` call it — strictly stronger, one definition (the request log's fixed catalog keeps it off the per-request hot path; the privacy test gains the new names); the query-param redaction stays `curlLogger`'s own. `requestToCurl(request, { excludeHeader })` is public and **does not redact by default** (v0 didn't — it's a faithful dev reproduction tool; a redacted curl can't reproduce the request), doc-pointed at `excludeHeader`, with `curlLogger` the redacting path; a malformed Host falls back to the path without its query, never a 500. F1: Authorization/Cookie/X-CSRF-Token/`?access_token=`/a password body field log none of their values; guard = a `defaultRedactHeader` that returns the value.

## Perf contract (from the audit — edge middleware must not defeat the fast paths)
- **Mutate the plain header record, never force native Headers.** Response-header-writing middleware (`rateLimit`'s `X-RateLimit-*`/`Retry-After`, `compress`'s `Content-Encoding`, plus `requestId`/`secureHeaders`/`poweredBy`/`serverTiming`/`cors`) write through `HoneyOutHeaders`'s plain-record path, not `#ensureNative()` — otherwise one header write collapses the lazy-header optimization and often triggers a response rebuild. The `mw-stack` bench scenario (all of them on one response) is the gate.

**Phase (b) prerequisite (ruled before cors — a closed-bit `out-headers.ts` change, and the `with-headers.ts` row moved 08 → 07):** the "plain-record write path" the contract above names **did not exist** — `set`/`append`/`delete` all called `#ensureNative()`, so one header write forced a native `Headers` on every response. It is built now:
- **(A) `HoneyOutHeaders` gains a real plain write path.** `set(name, value)` and `delete(name)` write the `#map` while `#native` is null (`append` stays native — only `Set-Cookie`/`Vary` lists need it; `Vary` via a read+set helper, `addVary`). **Copy-on-write** (an `#owned` flag, copy the map once on the first write) is **required**, not just an optimization: the response constructors pass the **frozen** `JSON_HEADERS`/`TEXT_HEADERS`/… constants as the map, so an in-place write would throw on the frozen object or corrupt a shared constant. **Validation is byte-for-byte native's** — a non-token name or a value with CR/LF/NUL throws the same `TypeError`; the response-splitting / header-injection guard is **unchanged and non-negotiable**, proven by the adversarial response-splitting case running green **against the plain path** (a `HoneyResponse` edited via `withHeaders`, not only the native path), plus `out-headers.test` growth: a write keeps `#native` unbuilt, write-validation parity with native, copy-on-write never touches the source map. Any header-injection guard must kill a mutant that skips the plain-path validation.
- **(B) `with-headers.ts` is born at bit 07** (row moved): `withHeaders(response, edit)` + `addVary`, the single response-editing helper every phase-(b) middleware uses; bit 08 extends it for declared response headers rather than creating it.
No wire behavior changes; the full suite stays green.
- **`compress` must honor the no-clone pin (bit 08):** encode from the retained raw, and hard-skip a produced stream (sse/stream/generate) — never buffer a body that may never end. Each edge middleware has a per-request cost ceiling in the perf gate; `rateLimit` store ops are O(1).
